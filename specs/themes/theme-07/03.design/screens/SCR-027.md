# SCR-027 — Chi tiết lấy hàng

## 1. Mục đích

Xác nhận quantity thực lấy theo allocation/LOT; đổi LOT đã pick phải reset và repick.

## 2. Use Case liên quan

- `UC-05-02`
- `UC-05-04`

## 3. Entry / Exit

### v2.8.2 — Scalable multi-LOT interaction

- The main screen no longer renders a full quantity field and action block for every LOT. Each allocation is a canonical `DS v2 / List Row (Navigation, Default)` showing `LOT`, `Cần`, and `Đã lấy`.
- Tapping one LOT opens a contextual canonical `VBottomSheet` to edit only that allocation. LOT override remains a separate contextual action from that editor.
- This keeps the overview scannable when many LOT allocations exist while preserving Product + UOM + LOT trace. The list may scroll naturally for large datasets; individual LOT editors do not accumulate vertically in the main page.

### Nội dung source còn lại / revision locks

### v1.4.1 — Inventory Operations UX correction

- Physical correction copy chuyển sang action-oriented “trả lô cũ / lấy lại lô mới”.
- Alternative LOT sheet giữ LOT + HSD + lượng có thể lấy nhưng helper ngắn hơn; không đổi rule no-preselection/reason/repick.

### v1.4.2 — Allocation vocabulary

- Multi-LOT section meta dùng `N lô cần lấy` thay cho technical `N phần phân bổ` khi allocations thực sự là LOT allocations.
- Product/UOM vẫn là parent context; mỗi LOT allocation là child task.

### v2.7.0 — Figma DS expression

- Picked quantity uses Figma `VTextField`. LOT override uses `DS v2 / Form Sheet` composition with `List Row/Selection`, `VRadio`, `VTextarea`, and a single primary footer action; no alternative is preselected.
- Business state, authority, commit/finality and recovery rules above are unchanged.

### v2.7.3 — Product-context density correction

- Product+UOM identity at the top of the screen uses `DS v2 / List Row` (`525:519`), `Type=Status`, `Density=Compact` (`370×52`) with trailing `Còn N UOM` context.
- `DS v2 / Summary Card` is not used for this sparse identity because it creates non-informative vertical space and its semantic responsibility is a grouped summary, not a generic entity header.
- LOT allocation behavior, physical-correction evidence and pick/commit rules are unchanged.

#### v2.7.4 UI correction

LOT replacement overlay is the canonical Figma Form Sheet (`1353:6355`). Typography, spacing, field sizes, close action, selection rows, textarea and disabled/enabled CTA states must be direct DS fidelity rather than feature-local approximations.

### v2.7.5 — Overlay correction

`Chọn lô thay thế` is a normal canonical `VBottomSheet` (`4695:6353`), not `DS v2 / Form Sheet`. It therefore has the standard drag handle/title/content anatomy and **no top-right close Icon Button**. The sheet hugs its business content, composes `List Row/Selection`, `VRadio`, `VTextarea` and one `VButton`, and may dismiss through the backdrop/drag interaction contract. This supersedes the v2.7.4 Form Sheet expression.

### v3.9.3 — Deep-review semantic closure

- Product identity no longer uses a raw-quantity VBadge. `Còn cần lấy` is a Key-value fact. LOT rows use allocated/picked/consumed semantics. Physical correction requires explicit `Xác nhận đã điều chỉnh hàng`; re-entering picked quantity alone does not clear it. LOT expiry preserves DAY/MONTH/YEAR precision and alternative `Có thể lấy` comes from server `lot_pickable_quantity`.
