# SCR-084 — Chi tiết hàng thực nhận

## 1. Mục đích

Xử lý đúng một goods receipt line Product+transaction UOM; bốn phân loại là authoritative inputs, Tổng kiểm nhận và Vào tồn vật lý là derived; LOT date giữ precision nguồn DAY/MONTH/YEAR.

## 2. Use Case liên quan

- `UC-02-01`
- `UC-02-02`

## 3. Entry / Exit

Theo BJ/UIF nguồn.

## 4. Dữ liệu hiển thị / nhập

### 2. Quantity model — khóa tại v1.3.4

Không còn field nhập riêng **Số lượng thực nhận**.

Bốn field sau là **authoritative user inputs**:

- `Đạt`
- `Cách ly`
- `Hỏng`
- `Từ chối`

`Tổng kiểm nhận = Đạt + Cách ly + Hỏng + Từ chối`; `Vào tồn vật lý = Đạt + Cách ly + Hỏng` và chỉ hiển thị read-only/derived.

`Tăng tồn vật lý = Đạt + Cách ly + Hỏng`; `Từ chối` không làm tăng tồn.

Với Product `LOT`:
- mỗi LOT có đúng bốn input phân loại trên;
- tổng LOT derive từ bốn input;
- tổng line derive từ tổng các LOT;
- không có line-total input và không có LOT-total input.

### 3. Business guardrails

1. Document Product/UOM source-owned; Quick Product/UOM đã chọn ở `SCR-009`.
2. `NONE`: không render LOT.
3. `LOT`: lot code bắt buộc; expiry theo Product policy; manufacture date optional.
4. Document variance so sánh **derived total actual** với lượng còn chờ nhận.
5. `Chưa nhận lần này` zero toàn bộ bốn phân loại và không xóa source line.
6. Quick item có thể xóa có kiểm soát; Document item không xóa.
7. Back không demote item đã hoàn tất nếu không có dirty change.
8. READ_ONLY là true read-only: không add/delete/edit/footer `Xong`.

### v1.4.1 — Inventory Operations UX correction

- Không lặp helper “Tổng … được tính tự động”; `Tổng kiểm nhận` vẫn là derived summary từ bốn nhóm số lượng.
- LOT editor giữ Product/UOM/LOT/expiry evidence nhưng bỏ explanation không giúp user nhập liệu.

### v1.9.0 — Holistic action-ownership hardening

- `Xong` completes the one-item editing task and returns to the overview. It must not be represented as a visible `ACT-02-SAVE-DRAFT` action.
- **Quick mode:** `Xong` chỉ cập nhật session memory; không server/local draft, không command lưu.
- **Document mode:** persistence hiện hành của UC-02-01 vẫn do system/background contract sở hữu.

### v2.7.3 — Current Figma DS product-context expression

- The historical `VCard.readOnly` product-identity notation is superseded by the live Figma DS expression.
- The selected Product context uses `DS v2 / List Row` (`525:519`), `Type=Status`, `Density=Compact` (`370×52`). Title = Product; subtitle = SKU · transaction UOM; trailing context = remaining document quantity, `Đã chọn`, or `Chọn đơn vị` as applicable.
- In Quick mode, `Đổi` remains a separate contextual action only while the new line is still choosing Product; it is not embedded as a fake navigation affordance inside the read-only context row.
- Do not use `Summary Card` or increase card height to create visual weight when the identity has only one or two facts.
- UI authority for this expression is the live Figma Design System; the business/quantity/LOT rules above remain unchanged.

### v3.9.2 — Deep-review lock

- `Từ chối > 0` phải có supporting text **Không vào tồn**.
- Over-source/tolerance dùng accepted physical base quantity; không dùng riêng `Đạt`.
- HSD/NSX input cho phép DAY/MONTH/YEAR và giữ original precision. Backend normalized date là contract-only. Precision cao hơn có thể enrich nếu consistent + audit; mâu thuẫn block.
