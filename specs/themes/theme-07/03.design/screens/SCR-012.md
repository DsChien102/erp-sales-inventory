# SCR-012 — Kết quả nhận hàng

## 1. Mục đích

Hiển thị kết quả theo từng Product+UOM line; zero-impact document receipt nói rõ không có hàng vào tồn. UNKNOWN dẫn tới đối soát cùng operation identity, không blind retry.

## 2. Use Case liên quan

- `UC-02-04`
- `UC-02-05`

## 3. Entry / Exit

### 1. Identity & trace

| Thuộc tính | Contract |
|---|---|
| Surface | `result` |
| BJ / UIF | `BJ-02` / `UIF-02` |
| UC | `UC-02-04`, `UC-02-05` |
| Execution owner | System |
| User mutation CTA | none |

## 4. Dữ liệu hiển thị / nhập

### 2. Experience contract

Trả lời: kết quả đã rõ chưa, từng dòng hàng có kết quả gì, bước tiếp theo là gì. Không cộng quantity xuyên UOM. Không CTA “Ghi nhận hàng”.

### 4. Result content

- Per item: Product + UOM + classification.
- LOT item: actual lot code + quantity + expiry khi có để truy vết, không chỉ lot count.
- Item `Chưa nhận lần này` vẫn thuộc **Kết quả theo dòng hàng**, vì không phải “hàng đã ghi nhận”.
- Valuation banner chỉ render ở `VALUATION_PENDING_RESULT`, không ở generic COMPLETED.

### Nội dung source còn lại / revision locks

### 3. State model

- `PROCESSING`: `VLoading`, không resend.
- `COMPLETED`: success `VEmptyState` + **`Kết quả theo dòng hàng`**.
- `VALUATION_PENDING_RESULT`: success result + `VBanner.info` chờ xác nhận giá.
- `REJECTED_EXECUTION`: danger `VEmptyState`, stock không đổi.
- `UNKNOWN`/`COMMIT_UNKNOWN`: giữ đúng lần nhận → `SCR-013`.
- `PERMISSION_DENIED`: `VEmptyState`.
