## 4. Dữ liệu hiển thị / nhập

### 2. Information hierarchy

1. Product identity ngắn: mã + tên; kho/as-of ở context.
2. **Khả dụng** là primary outcome duy nhất → `DS v2 / Key-value Row`, `State=Emphasis`.
3. Supporting facts `Tồn vật lý / Đủ điều kiện bán / Đã giữ` → `DS v2 / Key-value Row`, `State=Default`, để các số lượng căn thẳng theo cùng một trục.
4. Khi `physical > eligible`, hiển thị `eligibility_breakdown` theo reason; chỉ render reason có quantity > 0.
5. LOW/OUT nếu có → `VBanner`; `NOT_CONFIGURED` dùng supporting copy, không giả NORMAL; normal không banner.
6. LOT section nếu Product theo LOT → canonical `DS v2 / List Row`; LOT chỉ show physical/eligible/expiry, không show reserved/available trước allocation.
7. `Nguồn và thời điểm cập nhật` → canonical Navigation List Row mở `VBottomSheet`.
7. Trace sâu → BJ15.

Không metric grid, không lặp Khả dụng, không custom availability card/component, không over-card detail surface.

### 6. Read-only/security

No Add/Delete/Edit/Mutation footer. `Làm mới` is query only. `PERMISSION_DENIED` omits protected data from DOM.

## 9. Component composition

### 3. Component-selection proof

- Matching V-components used directly where applicable: `VAppBar`, `VBanner`, `VButton`, `VEmptyState`, `VBottomSheet`.
- No live V-named component owns the availability summary-outcome responsibility.
- Existing non-V `DS v2 / Key-value Row` is selected before any Product component because its `Emphasis` state is explicitly for totals/summary outcomes.
- `DS v2 / Info Row` remains valid only for simple supporting metadata; comparable inventory quantities use `Key-value Row` instead. `DS v2 / List Row` remains valid for navigation rows.
- `Theme7AvailabilitySummary` is forbidden from v2.4.3 onward. v2.4.4 also forbids Info Row for aligned quantity summaries. v2.4.5 locks typography ownership to the component variant: Default value = JetBrains Mono; Emphasis = Inter; there is no global “all numbers use Mono” rule.

### Nội dung source còn lại / revision locks

### 1. Primary task

Hiểu ngay sản phẩm còn bao nhiêu **khả dụng**, vì sao có con số đó, có vấn đề gì cần chú ý và — nếu theo LOT — lô nào liên quan.

### Historical v2.7.3 — Superseded by v3.9.1

- The v2.4.5 visual expression of `Khả dụng` as a standalone Emphasis Key-value Row is superseded for the current renderer.
- Product identity and the primary availability outcome are one scan context and now use `DS v2 / List Row` (`525:519`), `Type=Status`, `Density=Compact`: title = Product, subtitle = SKU · UOM, trailing badge = `Khả dụng N UOM`.
- Supporting quantities `Tồn vật lý / Đủ điều kiện bán / Đã giữ` remain separate comparable facts and stay in canonical `Key-value Row` instances inside one content-sized information surface.
- Do not add data merely to fill a fixed card. `Summary Card` is reserved for an actual narrative/decision summary; sparse identity/context should use the lighter canonical primitive that matches its responsibility.

### v3.9.1 — Current semantic expression (supersedes v2.7.3 detail expression)

- Product identity là compact read-only context **không badge**.
- `Khả dụng` quay về canonical `DS v2 / Key-value Row`, `State=Emphasis`; đây là metric, không phải status.
- Supporting quantities: `Tồn vật lý / Đủ điều kiện bán / Đã giữ`.
- `eligibility_breakdown` giải thích phần `physical - eligible` khi > 0.
- `query_as_of` hiển thị bằng copy `Dữ liệu đến`; refresh không lấy client clock.
- `NOT_CONFIGURED` là monitoring state riêng.
