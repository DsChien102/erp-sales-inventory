### Nội dung source còn lại / revision locks

### v1.4.1 — Inventory Operations UX correction

- Summary dùng `dòng hàng`; actual quantity vẫn trình bày theo từng Product/UOM/LOT, không cross-UOM aggregation.
- Normal execution rule là quiet helper/footnote; banner chỉ dùng cho source changed/blocker.

### v1.4.2 — Review vocabulary

- Summary dùng `dòng hàng trong lần này / dòng hàng chưa hoàn tất` thay cho `dòng hàng` mơ hồ.
- Per-allocation actual handover và mixed-UOM safeguards giữ nguyên.

### v2.7.0 — Figma DS expression

- Context uses `Info Row`; summary uses `Key-value Row`; actual handover stays per Product/UOM/LOT with `VTextField` when partial is allowed. No generic review card wrapper.
- Business state, authority, commit/finality and recovery rules above are unchanged.

### v2.7.5 — Handover hierarchy correction

The review screen groups handover data by Product + UOM, then by LOT/allocation. Each product is one information surface; each allocation shows LOT, picked evidence and the canonical quantity field `Lượng thực giao`. The section copy must explain the task directly (`Xác nhận hàng đã giao` / `Nhập lượng thực tế theo từng lô`) rather than using ambiguous helper text. Quantities from different UOMs are never aggregated.

### v2.9.3 — Grouped handover collection

- Supersedes “each product is one information surface”. The complete homogeneous handover set uses one Layout `Grouped surface` (`4518:1545`); repeated Product+UOM entries are subgroups, not cards.
- Product+UOM = `List Row / Status / Compact` with semantic `Đã lấy`; quantity stays in allocation `Key-value Row` / `VTextField` data.
- When actual handover is read-only, do not duplicate picked quantity in a second Info Row.

### v3.9.3 — Deep-review semantic closure

- Review only exposes `picked - consumed` as handover-eligible quantity. Quantity input uses Product+UOM precision/step. Commit writes immutable HandoverEvidence and increments consumed; it never shrinks allocated/picked/requested facts.
