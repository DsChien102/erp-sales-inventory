# Môi trường ERP (development / staging / production)

## Tổng quan

| Flavor | `APP_ENV` | Bundle ID | Supabase | TestFlight |
|---|---|---|---|---|
| `development` | `development` | `com.dschien.erp.dev` | Dev project (remote) | Không |
| `staging` | `staging` | `com.dschien.erp.staging` | Staging project | App ASC riêng |
| `production` | `production` | `com.dschien.erp` | Production project | App ASC chính |

Messaging worker Railway: `staging` / `production` — map 1:1 với ERP staging/production.

## Vet45 environments (`development` vs `local`)

| Manifest ID | Khi nào dùng | Supabase |
|---|---|---|
| `development` (default) | Remote dev project | `.vet45/profiles/<profileId>/development.env` + `supabase link` on use/sync |
| `local` | `supabase start` trên máy | `supabase status` — không đổi linked project |
| `staging` / `production` | TestFlight / Railway | Secrets + `supabase link` |

## Config files

```
vet45.workspace.json      # Committed — environments + scan (no profiles)
apps/*/vet45.target.json  # Committed — per-app keys + descriptions + bindings
deploy/vet45.target.json
.vet45/profiles/<profileId>/       # Local profile (gitignored; vet45 init generates examples)
deploy/deploy.env  # APP_STORE_CONNECT_* — shared iOS deploy
apps/erp/.env*            # Generated by melos run env:sync (gitignored)
apps/admin/.env*
apps/messaging_worker/.env*
```

SSOT for scaffold comments/keys: `keys[]` in each `vet45.target.json` (`description` required except `fromManifest`). Run `vet45 example` / `melos run env:example` to regenerate.

**Runtime:** `--dart-define-from-file` khi `flutter run` / `flutter build` — keys bake vào binary lúc compile.

Keys bake vào app: `APP_ENV`, `SUPABASE_*`, `LOG_LEVEL`, `MESSAGING_CLIENT_POLL_ENABLED`.

Keys **không** sync vào `apps/erp/.env` (deploy-only):

- `APP_STORE_CONNECT_ISSUER_ID`, `APP_STORE_CONNECT_KEY_IDENTIFIER` — trong `deploy/deploy.env` (dùng chung staging/production)

### Setup lần đầu

```bash
melos bootstrap
vet45 init mylocal
# Điền Supabase URL + keys trong .vet45/profiles/mylocal/*.env

melos run env:sync
melos run env:doctor
```

Chi tiết tool: [environment-manager.md](environment-manager.md).

## Chạy local

```bash
melos run env:list
melos run env:use:development   # remote dev + supabase link
melos run env:use:local       # supabase start only
melos run env:use:staging
melos run env:sync
melos run debug
melos run debug:staging
melos run worker:serve
```

## Build & TestFlight

```bash
melos run env:use:staging
melos run build:ios              # build only — active env
melos run deploy:ios             # build + upload — active env

# hoặc shortcut:
melos run build:ios:staging
melos run deploy:ios:staging
```

Low-level scripts (same manifest sync):

```bash
./apps/erp/scripts/build_ios.sh --env staging
./apps/erp/deploy-ios.sh --env staging
```

`APP_STORE_CONNECT_*` trong `deploy/deploy.env` (một file cho mọi flavor iOS).

Xem [testflight-asc-setup.md](testflight-asc-setup.md) để tạo app ASC staging/production.

## Đồng bộ messaging worker

Chưa có hosting cho worker (Railway / CircleCI đã gỡ). Chạy local: `melos run worker:docker` hoặc `melos run worker:serve`. Build + push image: `WORKER_IMAGE=<registry>/messaging-worker vet45 run worker publish`.

Khi chưa có worker chạy cho môi trường đó, giữ `MESSAGING_CLIENT_POLL_ENABLED=true` trên ERP để client tự poll outbox.

## iOS flavors

Schemes: `development`, `staging`, `production` trong `apps/erp/ios/Runner.xcodeproj/xcshareddata/xcschemes/`.

Chạy lại setup nếu cần: `python3 apps/erp/ios/scripts/setup_flavors.py`
