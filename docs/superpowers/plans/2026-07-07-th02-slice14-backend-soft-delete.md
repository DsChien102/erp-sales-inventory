# TH-02 Slice 14 Backend Soft Delete Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement backend lane for TH-02 slice #14 (`EPIC-07/US-03`) so Catalog can check deletion eligibility, soft delete a product, and restore a soft-deleted product through CQRS handlers, Supabase RPC adapters, draft SQL, generated access metadata, and BE tests.

**Architecture:** Follow the existing Catalog CQRS/module flow: command/query classes in `modules/catalog/application`, handlers delegate through application ports, infrastructure implements the ports through Supabase RPC, and codegen registers annotated handlers. Soft delete is an `isSoftDeleted` flag, not a `ProductStatus.deleted`; restore always returns the product to `ProductStatus.inactive` with refreshed readiness.

**Tech Stack:** Dart, `vet45_shared_application`, `vet45_catalog_domain`, `vet45_catalog_application`, `vet45_catalog_infrastructure`, `vet45_generator` codegen, Supabase RPC draft SQL.

## Task 5: Draft SQL for Soft Delete RPCs

**Files:**
- Create: `supabase/migrations/_drafts/12_catalog_product_soft_delete.sql`

**Interfaces:**
- Produces draft RPCs:
  - `catalog.check_product_deletion_eligibility(p_tenant_id uuid, p_product_id uuid)`
  - `catalog.delete_product(p_tenant_id uuid, p_actor_id uuid, p_product_id uuid, p_reason text, p_expected_version bigint, p_confirm_acknowledge_warnings boolean)`
  - `catalog.restore_product(p_tenant_id uuid, p_actor_id uuid, p_product_id uuid, p_reason text, p_expected_version bigint)`

- [ ] **Step 1: Draft eligibility RPC**

Implement tenant + permission guard using `iam.has_permission(p_tenant_id, 'catalog.product.delete')`.

Foundation dependency facts:
- `has_stock`: true when current basic stock quantity is non-zero if stock tables exist in current draft/schema.
- `has_historical_transactions`: false until Sales/Inventory historical contract exists, unless current schema already exposes a safe fact.
- `open_transaction`: false until TH-04/Sales contract exists.
- `active_promotion`: false until Promotions contract exists.

Return `can_delete=false` if any blocker exists; for warning-only facts return `can_delete=true`, `issues` with severity `warning`, and `suggested_action_id='deactivate_product'`.

- [ ] **Step 2: Draft delete RPC**

Rules:
- product must exist in tenant.
- if `p_expected_version` is non-null and stale, raise `stale_product_version`.
- if already soft deleted, return validation/application error.
- call eligibility logic inside transaction; blockers raise `product_delete_blocked`; warnings require `p_confirm_acknowledge_warnings=true`.
- update only soft-delete fields/version, preserving profile, units, images, stock, base price, price bands, custom fields, and change history.
- insert change history entry with before/after `is_soft_deleted`.
- return `ChangeProductSoftDeleteResult` row shape.

- [ ] **Step 3: Draft restore RPC**

Rules:
- product must exist and be soft-deleted.
- version guard same as delete.
- duplicate SKU/barcode check against non-deleted products in the same tenant.
- set `is_soft_deleted=false` and `business_status='inactive'`.
- insert restore change history entry.
- return refreshed readiness summary and history entry.

- [ ] **Step 4: Do not apply migration**

Do not run `supabase db reset` or promote the draft. This lane maps code to the draft contract and tests through fakes/mapper/unit tests.
